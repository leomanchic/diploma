# Проверка подтверждения трека тремя станциями

Дата: 2026-09-27. База: `e85bc51bcdb843e8f4ed7073ee1bae30a3dd1429`.
Протокол `ROBUST_TRACK_CONFIRMATION_PROTOCOL.md` зафиксирован коммитом
`c4878a0` до новых оценочных аудиозапусков. Восемь известных случаев
предыдущей диагностики использованы только для разработки и регрессии.

## Что изменено

Единственный opt-in вариант требует последующие подтверждающие пеленги от
трёх станций вместо двух (`confirmation_station_count=3`). Строительство
кандидата из шести событий, bounded consensus, tentative hypothesis,
retarded-time predictive NIS, окончательный consensus refit и recovery —
существующие механизмы. События для построения/подтверждения отмечаются как
initialization и не становятся независимыми EKF-коррекциями. Разные станции
прогнозируются на свои времена излучения. Вся обработка причинна: гипотеза
получает только уже доступные события. При выключенной опции прежний default
`confirmation_station_count=2` и численные результаты не меняются. `R`,
calibration bias, `Qc`, история, геометрия, акустические методы и предел 128
nonlinear fits одинаковы. Истинные координаты и скорость не входят в tracker;
они нужны только для синтеза сигнала и анализа сохранённых результатов.

Подтверждение означает согласованность доступных пеленгов с принятой моделью,
но не точность координат. При слабой радиальной наблюдаемости даже
подтверждённый трек может иметь ошибку в сотни метров. Для каждого валидного
состояния сохранены положение, скорость, полные блоки их ковариации, главные
полуоси и направления номинальных 95%-эллипсоидов, radial/transverse error,
position/state NEES, покрытие, время последней принятой коррекции и интервал
без коррекции. Эллипсоиды основаны на локальном гауссовом приближении; их
эмпирическое покрытие измеряется отдельно.

## Диагностические поправки

`historical_corrections_v2/variant_summary_v2.csv` исправляет четыре строки
budget exhaustion: причина в журнале — `computational_budget_exceeded_before_fit`.
Время согласовано между batch-fit, lifecycle и опубликованной
`initialization_summary.csv`. Все исходные таблицы, 120 опубликованных
`run_id`, записи Gazebo и исходный manifest оставлены побайтово неизменными.
Происхождение и SHA таблиц сохранены в `correction_manifest.json`.

Исторические `updates` не содержали фактический angular residual. В
`residual_availability_v2.csv` для всех старых updates стоит
`not_recorded_in_v1`; значения не восстановлены из NIS. Новые updates
сохраняют сам residual до коррекции, его норму, innovation covariance,
pre-update NIS и явную причину отсутствия остатка. Повторный расчёт
`rᵀ S⁻¹ r` в runner и отдельном тесте совпадает с NIS. Малый NIS не
доказывает малый угловой residual: значение зависит и от `S`. Успех
ideal-bearing при том же лимите fits также не исключает влияние лимита
на шумные случаи. Поправки внесены и в
`LOCALIZATION_ERROR_ATTRIBUTION_REPORT.md`.

## Данные и парное сравнение

Два существующих движения PX4/Gazebo: `single_turn` и `opposite_turns`.
Три дальности 200, 700 и 1000 м, две новые реализации шума на каждую
комбинацию: 12 непрерывных аудиопотоков. Исходный сигнал взят из прежних
сохранённых source banks. Модель `1/r` с фиксированным фоном и
`SNRref=10 dB`; параметры GCC/WLS, SRP, калибровка и cadence прежние.
Пеленги каждого потока сохранены один раз, затем одно и то же расписание
событий используется baseline и opt-in для обоих методов: 48 запусков
трекера, 24 парных method-stream сравнения. Хеши записей, источников,
пеленгов, конфигурации кода и всех результатов проверяются до агрегирования.
Разные дальности используют те же два движения и спаренные noise seeds;
перекрывающиеся кадры не являются независимыми испытаниями.

## Итог заранее заданного критерия

**Улучшение подтверждено в ограниченном протоколе.** Среди 24 пар
method-stream число первых подтверждений с ошибкой положения >50 м упало с
**13 до 11** (требовалось снижение минимум на 2). Любое подтверждение
получено в **21/24** случаях у обоих вариантов (допуск потери не более 2).
Общая доля подтверждённых публикаций — **0,6934 → 0,6704**, снижение
**0,0230** абсолютной доли при допуске 0,10. Медианное изменение времени
первого подтверждения среди общих подтверждённых пар — **0,00 с** при
допуске +1,00 с. Все четыре условия были записаны до оценки в протоколе.
Это не доказательство надёжной координатной локализации: новый вариант всё
ещё подтверждает 11 сильно ошибочных начальных состояний из 24 сравнений.

У GCC 3 из 12 потоков не подтвердились в обоих вариантах: все три исчерпали

На `opposite_turns`, 700 м, replicate 1 начальная ошибка GCC уменьшилась с

## Как проверить и повторить

```bash
cd ~/projects/diploma-gazebo/uav_acoustic_model
source .venv/bin/activate

# Проверить все сохранённые 12 потоков и их SHA; завершённые записи не
# синтезируются и не пересчитываются.
python -m analysis.robust_track_confirmation run-all \
  --output results/robust_track_confirmation
python -m analysis.robust_track_confirmation aggregate \
  --output results/robust_track_confirmation

# Создать независимый повтор 12 потоков в НОВОМ каталоге.
python -m analysis.robust_track_confirmation init \
  --output results/robust_track_confirmation_repeat
python -m analysis.robust_track_confirmation run-all \
  --output results/robust_track_confirmation_repeat
python -m analysis.robust_track_confirmation aggregate \
  --output results/robust_track_confirmation_repeat
python -m analysis.robust_track_confirmation correct-archived \
  --output results/robust_track_confirmation_repeat

# Notebook читает существующую основную запись и не запускает аудиосинтез.
jupyter nbconvert --to notebook --execute --inplace \
  notebooks/robust_track_confirmation.ipynb
```

В `results/robust_track_confirmation/evaluation_manifest.json` зафиксированы
протокол, runner, SHA текущего обработочного кода, исходные записи и source
banks, вся конфигурация и 12 seeds/run IDs. У каждого потока есть собственный
`experiment.json` с SHA пеленгов и всех результатов. `run-all` проверяет
целостность и пропускает завершённые потоки; `aggregate` дополнительно
проверяет все результаты до вычисления таблиц. Прямая перезапись готового
потока не требуется.

## Границы интерпретации

- Это две прежние формы движения и прежние source banks с новым шумом, а не
  новые полёты, реальные шумы или полевая валидация.
- 12 потоков недостаточны для надёжной оценки редких отказов, P99 и дальности
  системы. Подтверждение само по себе не означает полезную координату.
- Разные дальности разделяют движение и noise seeds. Сравнение выполняется по
  24 method-stream парам, кадры и методы одного потока коррелированы.
- Условные ошибки по валидным публикациям нужно читать рядом с долей
  доступности и отказами. Малое значение после отсева трудных кадров не
  означает улучшения всех потоков.
- Номинальный 95%-эллипсоид — локальная модель неопределённости. NEES и
  фактическое покрытие проверяются отдельно; ни эллипсоид, ни порог NIS не
  являются гарантией координатной точности.
- Wall-clock время собрано при частично параллельной обработке независимых
  потоков. Счётчик fits и peak history memory надёжнее характеризуют
  стоимость изменения; runtime приведён описательно, без строгого
  hardware-normalized сравнения.
